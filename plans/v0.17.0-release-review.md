> **Status:** Ready for review and release. All code, tests, CLI, HTTP, docs, and
> behavior spec are in place and verified. This doc is the checklist for tagging
> and shipping.
> **Author:** Forge
> **Date:** 2026-06-21
> **Predecessor:** `v0.16.0` (named vector spaces, embedding profiles, multi-space fusion)
> **Successor (consumer):** vidtrace named-vector-space adoption plan (`plans/vidtrace-named-vector-space-adoption.md`)

## Why this release exists

`v0.16.0` shipped named vector spaces but left two gaps in the API surface
that the single-vector API had closed for years:

1. **No key-based upsert for multi-space records.** `UpsertTextDocumentByKey`
   worked for text-only records, but the named-space equivalent
   (`InsertRecord`) upserted by numeric `ID`, not a payload key. Consumers
   with natural keys (vidtrace's `evidence_id`) had to do a manual
   `Find`-then-`InsertRecord` round-trip, losing `CreatedAt` preservation.
2. **No hybrid search over a named space.** `HybridSearch` ran the vector
   half against the default space only, so consumers storing vectors in a
   named `text` space couldn't fuse vector + BM25 results without manual
   `SearchSpace` + `TextSearch` + `FuseRRF` wiring in every call site.

`v0.17.0` closes both gaps with two additive methods, mirrors them across the
CLI and HTTP server, and documents the consumer-side migration recipe that
`v0.16.0` consumers (vidtrace in particular) need.

## What changed

### Library API (`collection_spaces.go`)

#### `UpsertRecordByKey`

```go
func (c *Collection) UpsertRecordByKey(keyField string, keyValue any,
    in RecordInput) (uint64, bool, error)
```

- **Location:** `collection_spaces.go:747`
- **Behavior:** Scans for an existing record whose `payload[keyField]` equals
  `keyValue` (using the same type-aware `compareValues` as payload filters).
  If found, routes through `insertRecordLocked` with the resolved `ID` so the
  existing replace path clears old vectors from every index and preserves
  `CreatedAt`, `ExpiresAt`, `Importance`, `AccessCount`, `LastAccessedAt`.
  If not found, inserts a new record.
- **Returns:** `(id, inserted, error)` — `inserted` is `true` for a new
  record, `false` for a replaced one.
- **Validation:** `keyField` must be non-empty (else `ErrInvalidVectorSpace`);
  each key of `in.Vectors` must be `DefaultVectorSpace` (or `""`) or a space
  declared via `AddVectorSpace`.
- **Bookkeeping preserved on replace:** `CreatedAt`, `ExpiresAt`,
  `Importance`, `AccessCount`, `LastAccessedAt` — matching
  `UpsertTextDocumentByKey` semantics.
- **Subscribers:** notifies subscribers after a successful upsert (via
  `c.notifySubscribers(record)`).

#### `HybridSearchSpace`

```go
func (c *Collection) HybridSearchSpace(space string, query []float32,
    text string, opts ...SearchOption) ([]Result, error)
```

- **Location:** `collection_spaces.go:803`
- **Behavior:** Vector half runs `SearchSpace(space, query, ...)` against the
  named space (or the default space when `space` is `""` or
  `DefaultVectorSpace`); text half runs `TextSearch(text, ...)` over the
  collection's single BM25 text index; the two result sets are fused with
  `reciprocalRankFusion` (k=60, weights configurable via `WithVectorWeight`
  and `WithTextWeight`).
- **Requires:** text indexing enabled via `WithTextIndex` (returns
  `"veclite: text index not enabled on this collection"` otherwise).
- **Default-space shortcut:** passing `""` or `DefaultVectorSpace` is
  equivalent to `HybridSearch`.
- **Fetch strategy:** fetches `topK * 2` (min 20) from each source before
  fusion for better ranking quality.

### CLI (`cmd/veclite/spaces.go`, `cmd/veclite/main.go`)

Two new commands, wired into the dispatcher and usage text:

```
record-upsert-by-key <file> <collection>  Insert or replace a record by payload key
hybrid-search-space <file> <collection> [space]  Search a named space + BM25, fuse with RRF
```

**`record-upsert-by-key` flags:** `--key-field` (required), `--key-value`
(required), `--vectors` (JSON map, required), `--content`, `--payload` (JSON),
`--json`. Output (JSON): `{ "status": "inserted"|"replaced", "collection",
"id", "inserted", "key_field", "key_value" }`.

**`hybrid-search-space` flags:** `--query` (JSON array, required), `--text`
(required), `--top-k` (default 10), `--threshold`, `--filter`, `--json`. The
`<space>` positional is optional and defaults to `default`. Output is the
standard search-result array.

### Bonus CLI fix

`create-collection` gained a `--text-index=<comma-separated-fields>` flag.
This was a real gap — without it, hybrid search (which requires
`WithTextIndex`) couldn't be exercised from the CLI at all. The README's
CLI examples already referenced `--text-index=title,body`; the flag now
actually exists.

### HTTP server (`cmd/veclite/server.go`, `cmd/veclite/server_spaces.go`)

Two new endpoints, wired into the collection router:

| Method | Endpoint | Handler |
|--------|----------|---------|
| POST | `/collections/{name}/records-upsert-by-key` | `upsertRecordByKey` |
| POST | `/collections/{name}/hybrid-search-space` | `hybridSearchSpace` |

**`records-upsert-by-key` body:** `{ "key_field", "key_value", "content",
"payload", "vectors" }` where `vectors` is `map[string][]float64` (converted
to `[]float32` server-side). Response: `{ "status", "id", "inserted",
"collection" }`.

**`hybrid-search-space` body:** `{ "space", "query" ([]float64), "text",
"top_k", "threshold", "filters" }`. Response: the standard
`{ "results", "count" }` envelope via `writeSearchResults`.

### Behavior spec (`specs/glyphrun/cli_named_space_upsert_and_hybrid.yml`)

A new glyphrun spec covering the full CLI lifecycle end-to-end:

1. Create a collection with `--text-index=label` and a named `text` space.
2. Upsert record `apple` by `evidence_id=apple` (insert, `id=1`).
3. Upsert record `banana` by `evidence_id=banana` (insert, `id=2`).
4. Re-upsert `apple` by the same key with changed content (replace, `id=1`
   preserved, `status=replaced`).
5. Hybrid search the `text` space — `apple` ranks first.
6. Verify both records appear in the fused ranking.
7. Verify idempotency: two consecutive upserts of the same key return the
   same `id`.
8. Verify default-space fallback (omit the `<space>` positional).
9. Verify an unknown space is rejected.

All steps were verified by hand against the built CLI before writing the
spec; the spec is the regression guard.

## What was NOT changed (intentionally)

- **No breaking API changes.** Both new methods are purely additive. The
  entire single-vector API and the `v0.16.0` named-space API work unchanged.
- **No storage format bump.** The on-disk format stays at v4; databases
  written by `v0.16.0` load unchanged.
- **No new collection-management methods.** `RenameCollection` and
  `MergeCollections` were considered and rejected — the migration recipe in
  the README covers the use case with existing APIs.
- **No MCP server changes.** The MCP tool surface is out of scope for this
  release; the two new methods are available to MCP consumers via the
  underlying library.

## Post-release: what this unblocks

Once `v0.17.0` is tagged, the vidtrace consumer migration
(`plans/vidtrace-named-vector-space-adoption.md`, Phases 1–4) can proceed.
The migration collapses vidtrace's three collections
(`evidence_entries_keyword` + `evidence_entries_text` + `evidence_meta`) into
one `evidence_entries` collection with a named `text` space, using:

- `UpsertRecordByKey("evidence_id", id, RecordInput{...})` for idempotent
  re-indexing (Phase 1).
- `HybridSearchSpace("text", queryVec, query, ...)` for hybrid search
  (Phase 2).
- The README migration recipe for `vidtrace migrate-evidence` (Phase 3).

Estimated effort: ~2 days, self-contained in the `vidtrace` repo.
